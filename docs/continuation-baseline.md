## 3. 当前测试的解释

- `tests/contracts/**`：证明局部数据结构与单进程契约，可作为后续回归。
- `tests/integration/**`：证明当前 Node 入口的局部集成；不能替代 MongoDB、网关、浏览器、客户端和干净环境。
- `modules/*/tests/**`：证明最小模块接口；不能据此宣称 P3–P7 产品完成。
- `deploy/validate-presets.js`：只做静态组合检查；镜像、端口、健康检查和协议必须以 C30–C32 的真实运行结果为准。
- `tools/verify-release.js`：发布前检查工具；退出码、清单存在和扫描排除规则都不是实际制品验收。

## 4. C03 冻结的施工契约

详细字段和不变量见 `contracts/runtime-topology.json` 与 `contracts/runtime-contracts.md`。摘要如下：

1. 首版沿用 Node 公共宿主与 Node Glim；不虚构 Python Glim 服务。Python 只允许作为受控 worker 内的工具运行时。
2. 必要运行单元为网关、Node app、MongoDB，以及按模块需要启动的执行 worker；Disk 独立进程是可选优化而非第二数据权威。
3. 所有持久化适配器使用异步接口。`InMemoryStore`、`JsonStore` 和同步 `Map` 仅限测试或明确演示，正式启动不得静默回落。
4. HTTP 路由必须声明 `json`、`binary`、`upload`、`download` 或 `sse`；小型 JSON 限额不能约束大文件，下载不得经过 `JSON.stringify(Buffer)`。
5. 文件内容、元数据、修订与操作提交分离；任何模块写入都进入所属模块适配器、配额和同一变更日志。
6. 任务必须有持久 ID、状态、取消与超时语义；浏览器断开不能留下无界进程，外部副作用必须可幂等解释。
7. 模块选择、注册、Disk 策略、模型引用、固定数据根和服务地址来自版本化配置。未选择模块不得加载业务入口、启动任务或要求专属秘密。
8. 依赖安装、容器构建、缓存与测试数据放仓库外隔离构建区；禁止加载生产 `.env`、连接生产服务或以开发身份头代替正式会话。
